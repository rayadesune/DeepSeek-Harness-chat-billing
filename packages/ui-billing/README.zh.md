# @rayadesu/dsh-client-ui-billing

[English](README.md) | 中文

Web 额度特性的归属方：贡献三个会话级条目——这里描述的右上角徽标（`conversation.session.header.utilities`）、操作条里的本轮花费条目、以及输入框 dock 里的花费 pill（后两者见下）——并在它们背后挂载自己的 `billing` Remote。徽标条目渲染 DeepSeek 账户余额与今日所有会话的计费花费（`billing/getTodaySpend`）——徽标是账户级的；本会话的计费花费（本会话自身的花费读宿主推送的 `billingTodaySpend` 投影，投影注册表不存在时回退 `billing/getSessionSpend`；再加上它委派的子代理会话，来自 `billing/getDelegatedSpend`）归下面的输入框花费 pill，不归徽标——今日按会话的排行（`billing/getTodaySessionsSpend`，每行一个**对话**——宿主已把每个子代理会话的花费并入委派它的那个会话行里）与各回合花费（`billing/getSessionTurnSpends`），在右上角渲染成一个标签框。该能力的宿主侧在 [`dsh-llm-billing`](../llm-billing/README.md)，它拥有 `/user/balance` 传输、峰谷计价表与 `billing` Remote 命名空间；本包挂载那个 Remote 并渲染它返回的内容。

触发器显示两行——剩余余额与今日所有会话的计费花费——主行是面板标题文案去掉 `API` 前缀的短版（`剩余金额`，徽标较窄），副行用的就是面板的 `label.todaySpend`（`今日花费`），一字不差——两者读的是同一份 state，所以不可能互相矛盾；它是账户级的：只在当日自身的读取（挂载、手动刷新、回合定稿、打开面板）时变动，不随回合实时跳；有上次已落定的余额就立即渲染（按插件实例保留），后台校验；首次余额尚未到达时不渲染任何东西。点击后展开一个标签框：剩余金额（后面跟着按余额序列算出的今日消费，见下文「余额序列口径的今日消费」）、今日计费 token 数与今日所有会话合计（「今日 Token」与「今日花费」同一行——token 数把每个计价行的三个计费桶相加，缓存读取与输出各算一个 token，并按 DSH 自己的紧凑记数法加 ` tok` 单位渲染：`517 tok`、`12.2K tok`、`1.2M tok`——<1e3 原整数、<1e6 用共享 `K` 单位、再往上用 `M`，缩放值 <100 保留一位小数、≥100 取整）——紧跟在 token 数值后面的是当天的**缓存命中率**（裸数字，无括号、无文字说明），按 DSH 官方命中率规则渲染：整数百分比，只有部分命中会被四舍五入到 100% 时才逐位多留小数（`99`、`99.5`、`99.95`），当天没有 prompt 侧输入就完全不显示——紧跟该行下面是**今日两行桶明细**（token 在上、花费在下，两行各自成行、各自保持自然的 ` · ` 间距，两行之间不做列对齐；桶名与行序用 DSH 的，排版与 DSH 自己的桶行同族，行距用第三部分（今日会话花费排行）那一套紧凑节奏；**所有花费金额都用 `formatSpendSignificant` 按三位有效数字渲染**（今日花费与它的三个桶、排行金额），但**不细于四位小数**——低于 ¥0.0001 的金额显示 `¥0`；只有余额行保持 `formatSpend` 的至多四位小数）、手动刷新按钮，以及「?」按钮上的一句简短花费说明（只估算 DeepSeek 与 MiMo 模型、按每条消息自身时刻的峰谷单价计价；下一行说明会话金额含它委派的子代理会话，最后一行顶格是纯版本号（如 `v0.3.13`）——构建期从本包 manifest 注入，便于反馈时指明所用版本；费率明细在宿主 README —— DSH 的悬停气泡只装得下短文案，过长会在视口边缘被裁掉——所以它不用 tooltip，而是在短暂停留后展开成一张悬浮说明卡：指针能移上去停留、能选中文字（四行说明是要读的，不是瞄一眼就该消失的），按 Esc 收起，纵向适配可翻转的那一侧）。剩余金额行（`API 剩余金额`）字号大于下方花费行（`今日 Token`／`今日花费`）。今日桶明细行下方是**今日会话花费排行**（`今日会话花费`）：按今日花费从高到低排列的**对话**列表（宿主已把每个子代理会话的花费并入委派它的那个会话行，所以一行就是一个对话，而不是一次委派），每行以右对齐的名次列开头，后接与花费分项相同的小圆点分隔符（「·」，字号、色调与间距一致），再是会话的持久标题（重命名自动同步），最后是金额——标题在名次列后缩进对齐；最多渲染 `SESSION_RANKING_LIMIT`（10）行，其余以「…还有 N 个会话」提示。刷新时旧值不消失，刷新失败保留上一次有效值。没有可计价消耗的会话或日子显示的是文字而不是编造的数字：确实没有用量时是「暂无消耗记录」；有用量却没有任何费率行覆盖时是「有消耗，但未匹配到费率」，并把未计价的模型名列出来——否则一个无声的 ¥0 与「今天没用」无从区分。失败——未配置 API key、凭据被拒绝、传输错误——渲染弱化的「额度不可用」徽标，而它打开的仍是金额状态下的同一个面板：第一行是简短的本地化文案 `notice.unavailable`（前缀就是这同一个词）提示检查 API key——Remote 的英文原文不在卡片里渲染，它留在徽标的无障碍名与宿主日志里——主行显示 `—`（总额未知），刷新按钮仍在原处，于是在一个地方就能知道该做什么并重试。另一种空态是：API 正常应答，但报告该 key 没有可用余额——这不算失败，徽标保持普通文案加 `—`，面板第一行只放 `notice.none`。两种空态都不隐藏当日花费：它来自会话日志，徽标第二行与面板的「今日 Token／今日花费」照常显示且保持更新。

本包还贡献**本轮花费条目**（`billing-turn-cost`，order 20）到 ui-chat 的 `conversation.chat.assistant-actions` list slot——与 `ui-message-feedback` 同一条操作条，多条目共存；条目自身的 CSS `order: 1` 把它排到所有 order-0 兄弟之后，金额因此落在操作行**行尾**（时钟之后）。它为每个已完成回合的收尾助手消息渲染一个纯静态 `¥X`（无图标、无文字标签、不可点击），金额来自每会话共享的 `messageId → 金额` 映射（`billing/getSessionTurnSpends`，每会话只拉一次，并发挂载的行共享同一请求；映射里没有的消息 id 只触发一次重拉，对应当前刚完成的回合）。回合没有 DeepSeek 用量（花费为 0）或加载失败时不渲染，Remote 故障不会污染操作行。

第三个条目是**输入框花费 pill**（`billing-spend`，order 20），挂在 ui-conversation 的 `conversation.composer.dock` list slot——ui-chat 自己的 token/时间 pill 所在的输入框下方统计行。`b6726fe79d` 已把该 dock 从纵向堆叠改成一条居中 flex 行（`InputBar.module.css` 的 `.dock`），所以 dock 条目现在是行内 flex 子项而非独占一行：ui-chat 统计注册 `order: 0`、本条目 `order: 20`，而输入框在 slot **之后**直接渲染 ContextMeter——整行从左到右即 `[时间/token] [¥ pill] [ContextMeter]`，pill 紧跟官方 token 右侧（ContextMeter 在回合运行时会自行隐藏；dock 本身只在常驻输入框且有会话时渲染，所以新会话 hero 页没有任何 pill）。pill 自身的度量逐项照抄同一行官方 pill 的 `StatsPills.module.css`，两者读起来是同一族：同一套 12px 字号公式（`calc(var(--dsh-content-font-size-secondary, 13px) - 1px)`）、等宽数字、三级色调、14px 图标、`padding: 1px 8px`、24px 圆角、6px 间距与同一 hover 底色；480px 以下金额折叠、只留图标（与同族的逐条消息用量 pill 一致）。条目本体是一枚品牌标记 pill（本包自己的「环 + 四角星」标记，为 14px 图标档把四角星填实），显示本会话的计费花费；点击向上弹出逐 token 复刻 ui-chat token 用量对话框皮肤的花费卡片（菜单底、12px 圆角、elevation-prominent、16px 内边距、标题行带主金额与 0.5px 分隔线、右对齐等宽数字网格）——标题是「花费金额」，三行就是花费的三个计费桶，用的正是 token 卡那套文案：**未缓存输入 / 缓存读取 / 输出**。金额是**整段对话**的，合并方式与宿主自己的汇总一致，且 pill 是**唯一**显示会话自身花费的界面（徽标第二行与面板报的都是当日口径）：本会话自身花费来自推送的 `billingTodaySpend` 投影（pill 自己不发 Remote 调用；`spendBuckets.ts` 把每模型行相加，并把四位小数的浮点残差并入最大桶，保证三行之和恒等于标题里的总额），投影缺失时回退 `billing/getSessionSpend`，**再加上** `billing/getDelegatedSpend` 的子代理小计、经 `sumSpends` 合并——所以 pill 与徽标不可能不一致——渲染精度也沿用徽标那套 `formatSpendSignificant`。本会话任何地方都没计价的会话不显示条目；自身没计价但委派的子代理烧了钱的会话**照常显示**（隐藏规则跑在合并后的金额上）。DSH 自带的同款 dialog 席位在其私有客户端 bundle 里、无法导入，所以定位与关闭由两个公开原语重建（`useAnchoredPosition` 与 `useDismissOnOutsidePointer`）。

角标是账户级的，尽管插槽是会话作用域：顶栏工具行不过是外壳提供的那个始终可见的标题栏席位，余额并不随会话变化——但花费行会，因为它按当前会话自己的用量（推送的投影，或 `billing/getSessionSpend`）计价、通过 `billing/getTodaySpend` 按所有会话的用量计价。文案走本包自己的 `billing` locale 命名空间；样式只用 token。

## 余额序列口径的今日消费

跟在 `API 剩余金额` 后的数字是纯粹的账户加减，不是 token 计价：**当天（本地自然日）第一次查询到的余额**减去屏幕上当前的金额，再加上期间余额上涨识别出的充值。充值是观测到的余额**上涨按 10 元步进向上取整**（厂商只按整十充值，所以「充 10 元、用掉 1 元」的 9 元净增长仍读作 10 元），正是这条规则让「先充值、再消费」的一天不会读成负消费。这就是本插件对标的 `balanceinfo` 桌面程序的口径（其 `utils/balance.ts` + `Dashboard.tsx`），并且**刻意与计价的「今日花费」分成两个数**：这个数是账户自身的加减，因此别的客户端花的钱、或本浏览器打开之前花的钱，只在这里体现；两个数字不一致是正常的。

本半面每次查询到的余额都会折叠进一份当日记录（`balanceDay.ts`），并写入 `localStorage`，所以当日的基准能跨页面刷新与 `dsh` 重启保留；记录按**本地自然日**翻篇（浏览器所在的日，而不是宿主的北京日键——只有浏览器知道读面板的人身处哪一天），新的一天从当天第一次查询重新起算。只有当天已有该币种采样时才渲染这个数字：没量到就什么都不显示，而不是显示一个会被当成实测值的 `¥0`。`getCachedBalance` 只是重放之前某次查询已经记过的值、不做采样，所以切换会话不会挪动基准。

由于余额在挂载、手动刷新之外，**页面可见时还会每 5 分钟轮询一次**（balanceinfo 本体就是这个节奏），落进同一个 5 分钟窗口的「充值 + 消费」会被看成一笔净变动，10 元步进正是避免它读成负消费的那条规则；因此这个数字反映的是本页面自己做过的采样，而不是逐分钟的账本。切换会话不采样：余额不随会话变化，切换只重取本会话自己的花费。页面隐藏时停止轮询，回到前台时立刻补一次。

## 数据更新机制

花费跟随会话、额度带缓存并按 5 分钟轮询：

- **取数按「依赖什么」分成两组** —— `billing/getSessionSpend` 与 `billing/getDelegatedSpend` 随会话变化，切换时会重取；`billing/getBalance` 与 `billing/getTodaySpend` 不随会话变化，因此各走自己的节奏（挂载、手动刷新、回合结束，以及面板打开时补读今日行），切换时不再重取。正是「每次切换都重取这两条」让右上角转圈转到当天那次全会话扫描结束，也让今日 Token 落在余额后面。
- **本会话花费靠推送，不靠拉取** —— 宿主把每个会话的花费折进客户端可见的 `billingTodaySpend` 投影并推送每次变化；消费它的是输入框花费 pill：pill 用框架 `useProjection` 座位订阅，因此投影注册表装配时会话金额零 Remote 调用、实时更新。键不存在时同一金额回退到 `billing/getSessionSpend`。徽标仍然跑着本会话这一组读取（与 pill 共用同一份宿主缓存），但它渲染的东西已经不读这组结果——第二行报的是今日花费，账户级、没有推送源。
- **今日花费随回合结束更新（去抖），并且带 `force`** —— 组件通过框架 `useSession` 座位订阅当前会话的「运行中」标志。每当一轮 prompt 回合结束（标志翻回空闲）就重算**今日花费**（`billing/getTodaySpend(true)`；同一行的**今日 Token** 由这次读取的模型行原地求和，不发额外请求）；重算有 2 秒去抖，回合突发（agent 连续多轮）只计价一次。这里**必须带 `force`**：这一轮刚刚改变了答案，普通（走缓存）读取会被回以「这一轮之前的值 + 后台刷新」，于是今日行每轮都慢一拍。同一次回合结束也强制刷新本会话的子代理小计（`billing/getDelegatedSpend(sessionId, true)`）——这正是让 pill 金额在子代理跑完后仍是「整次对话」口径的来源。**排行**（`billing/getTodaySessionsSpend`）只在详情面板打开时（以及手动刷新时强制）拉取，徽标一直关着就不会为全量会话扫描买单；排行之后最多滞后 60 秒。
- **打开面板会补读今日花费** —— 切会话只重取本会话那两条，所以用户在各会话之间浏览时，今日行一直是上一次读取的结果；打开面板正是读者「要看这个数」的时刻，因此除了排行之外还会重读 `billing/getTodaySpend`。两条都走缓存路径（不带 `force`）：宿主先给它手上的值，过了窗口则在答案背后刷新。
- **额度带 TTL 缓存 + 可见时轮询** —— 账户余额在挂载与点刷新按钮时拉取。宿主 15 秒内复用同一份快照（手动刷新带 `force` 绕过），单次请求 5 秒超时；浏览器保留最后一次已落定值，切会话时立即渲染、且不重新拉取（余额不随会话变化）。除此之外，**页面可见时每 `BALANCE_POLL_MS`（5 分钟）轮询一次**，页面隐藏则暂停、回到前台立刻补一次：余额序列口径的今日消费以「当天第一次查询到的余额」为基准，采样节奏就是这个数字的分辨率。
- **刷新保留旧值** —— 刷新在途时旧值留在屏幕上，刷新失败保留上一次有效值，不清空。刷新按钮调用 `billing/getBalance(true)`、`billing/getTodaySpend(true)`、`billing/getDelegatedSpend(sessionId, true)` 与 `billing/getTodaySessionsSpend(true)`，绕过宿主侧缓存；挂载、打开面板与切会话的读取走缓存路径，回合结束触发的重算则和手动刷新一样带 `force`。转圈只跟随**这次变化真正重跑的那一组**：切会话只等本会话那两条，手动刷新才等全部。

## 插件管理页的展示元数据

插件管理页上本包那一行显示的标题、描述与图标都取自包自身（宿主不执行任何插件代码）：

- `locale/en.json` 与 `locale/zh.json` —— 形状 `{"meta": {"title": …, "description": …}}`，按当前界面语言解析、回落英文。
- `icon.svg` —— 自包含 SVG（不引用任何外部字体或图片），由 `package.json` 顶层的 `icon` 字段声明。

两者都经包的 `exports` 解析，所以 `./locale/*.json` 必须保持导出——去掉它会让 locale 文件解析成 `ERR_PACKAGE_PATH_NOT_EXPORTED`，宿主把它当作「没有元信息」，静默回落到裸包名。`locale/*.json` 与 `icon.svg` 也必须留在 `files` 里，否则打出的 tarball 两个都不带。

## 模型体验

无，因为本包为人类渲染账户级的 provider 事实，不触及 prompt、消息、schema、流或工具结果。模型对 provider 额度的视角仍在 [`dsh-llm`](https://github.com/deepseek-ai/deepseek-harness/tree/main/packages/llm/llm) 在请求失败时抛出的 `QUOTA` / `INVALID_CREDENTIAL` 错误码里。

#### KV Cache effect

无；本包从不组装或发送 provider 请求，它唯一的 RPC 是一次带凭据的账户读取，不落在 provider 的 KV 缓存里。

## 已知限制与暂缓事项

- **只取首条余额线** —— 余额读取主要（`balance_infos[0]`）币种行；其它币种行不显示。
- **排行上限 10** —— 面板最多显示 `SESSION_RANKING_LIMIT` 个对话，其余以「…还有 N 个会话」提示。上限在宿主的子代理合并之后生效，所以一行就是一个对话，而不是一次委派。
- **子代理小计随回合更新，不逐事件跟进** —— pill 金额里本会话自身那部分是实时的（推送投影随回合更新），子代理那部分来自 `billing/getDelegatedSpend`：挂载、切换会话、手动刷新与回合结束时各拉一次，并与今日花费共用同一个 60 秒宿主缓存。因此子代理在回合中途烧掉的钱会在下一次读取时落到会话金额上，而不是逐事件实时跳动。
- **本轮花费需要已定稿的收尾消息** —— 中断的回合没有操作行，不显示本轮花费。
- **今日 Token 只数计价行** —— 它统计的是 `billing/getTodaySpend` 返回的那些模型行（即价目表里有费率行的模型）的三个计费桶之和；没有费率行的模型不计 token，缓存写入并入「未缓存输入」桶（与分项同一口径）。该行紧跟的命中率只按 **prompt 侧**两个桶算（缓存读取 ÷（缓存读取 + 未缓存输入）），输出不进分母，与 DSH `billedInputTokens` 的口径一致。
- **面板排版只有三级** —— 三级字体定义在面板样式表的 `.panel` 上（每个成员只引用自己那一级的 token，改一处即整级生效）：**一级** 11px/16px tertiary tabular-nums，用于桶明细行（`未缓存输入 ¥X · 缓存读取 ¥Y · 输出 ¥Z`）、今日会话排行整行（名次、分隔点、标题与金额）、「…还有 N 个会话」以及两个紧跟数字（余额后的今日消费、当天缓存命中率）；**二级** 12px/18px secondary，只用于 `今日会话花费` 标题——面板唯一的二级成员，且它不带数字，所以这一级不设自己的数字色调（**同一级里文字与数字的色调允许不同**，今后出现二级金额时照此办理）；**三级** 13px/18px primary tabular-nums，用于 `今日 Token`、`今日花费` 两行（含各自的紧跟数字）。
- **输入框花费 pill 自己有一套子代理读取节奏** —— 它在挂载、切会话、以及（强制的）回合落定边沿各读一次 `billing/getDelegatedSpend`，去抖与徽标同为两秒，因此一次落定徽标与 pill 各发一次强制读取。这重复目前是刻意的——宿主的 revision 门控让第二次代价很低——等日志显示它真的碍事，再抽成按会话共享的 store（`turnCostStore` 同款模式）。pill 只计价宿主费率表覆盖的模型（DeepSeek 与 MiMo），而旁边那条 token 行统计的是会话全部 token，缓存写入并入它的「未缓存输入」行。
- **额度在两次轮询之间最多旧 15 秒** —— 宿主 15 秒内复用同一份快照、浏览器保留最后一次已落定值：其他客户端产生的消耗会在下一次轮询（页面可见时 5 分钟一次，隐藏时没有轮询）、手动刷新或刷新浏览器时才体现在数值上。
- **余额口径的今日消费只反映「本浏览器看到过的采样」** —— 它按浏览器的本地自然日分桶，采样发生在挂载、手动刷新与**页面可见时的 5 分钟轮询**（切换会话不采样：余额不随会话变化），所以它反映的是本页面自己做过的采样，而不是连续的账本；两次采样之间发生的充值只会体现在净变动里，由 10 元步进向上取整补偿。当日记录存在本源的 `localStorage`，换一个浏览器（或清空存储）就从它当天自己的第一次采样重新起算。
