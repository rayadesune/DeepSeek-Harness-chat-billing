# @rayadesu/dsh-client-ui-billing

English | [中文](README.zh.md)

Web billing feature owner: contributes three session-scoped entries — the header badge (`conversation.session.header.utilities`) described here, the per-turn cost label in the assistant-actions strip, and the composer spend pill in the composer dock (both below) — and mounts its own `billing` Remote behind them. The header entry renders the DeepSeek account balance and today's spend across every session (`billing/getTodaySpend`) — the badge is account-level; this conversation's own billed spend (this session's own spend read from the host-pushed `billingTodaySpend` projection, with `billing/getSessionSpend` as the fallback when the projection registry is absent, plus the subagent sessions it delegated from `billing/getDelegatedSpend`) is the composer pill's below, not the badge's — and today's per-session ranking (`billing/getTodaySessionsSpend`, one row per conversation — the host has already merged every subagent session's spend into the row of the session that delegated it), and per-turn costs (`billing/getSessionTurnSpends`) as a top-right label box. The host half of the capability lives in [`dsh-llm-billing`](../llm-billing/README.md), which owns the `/user/balance` transport, the peak/off-peak pricing table, and the `billing` Remote namespace; this package mounts that Remote and renders what it returns.

The trigger shows two lines — the remaining balance and today's spend across every session — where the balance line is the panel's headline label without its `API` prefix (`剩余金额` / `Balance`, the chip being narrow) and the spend line is the panel's own `label.todaySpend` (`今日花费` / `Today spend`), word for word — the same state feeds the panel's own row, so the two cannot disagree; being account-level, it moves on the day's own reads (mount, the manual refresh, a settled turn, and a panel open) instead of with the turn; it renders immediately from the last settled balance (kept per plugin instance), revalidating in the background, and before the first balance ever lands it renders nothing. Clicking it opens a label box with the remaining amount carrying today's consumption measured from the balance series itself (see *Today's consumption from the balance series* below), then today's billed token count with today's all-session spend beside it (今日 Token / 今日花费, one row; the count sums the three billed buckets of every priced row, so a cache-hit input token and an output token each count once, and it renders in DSH's own compact notation with DSH's ` tok` unit — `517 tok`, `12.2K tok`, `1.2M tok`: below 1e3 the plain integer, below 1e6 the shared `K` unit, otherwise `M`, keeping one decimal under 100 and rounding from 100 up), with the day's cache-hit share right after that figure, bare and unparenthesized — DSH's own hit-rate rule, an integer percent that grows decimals only as far as a partial hit needs to stay below 100 (`99`, `99.5`, `99.95`), and nothing at all when the day billed no prompt-side input — then today's two bucket detail lines directly under it (tokens on top, costs below, each line on its own with its natural ` · ` spacing — no column alignment between them — typed like DSH's own bucket line but spaced on the third section's rhythm (the today session-spend ranking's tight 6px); DSH's bucket wording and row order; every spend amount renders at three significant digits via `formatSpendSignificant` — the day figure and its bucket costs, and the ranking amounts — but never finer than four decimals, so an amount below ¥0.0001 reads `¥0`; the balance line alone keeps `formatSpend`'s up-to-four decimals), a manual refresh action, and a short spend disclaimer on the `?` button (only DeepSeek and MiMo models are estimated, each message priced at its own peak/off-peak rate; the next line states that a conversation's amount includes the subagent sessions it delegated; and the last line is a bare version like `v0.3.13`, stamped in at build time from this package's manifest, so a report can name the build; the full rate schedule lives in the host README, because the DSH tooltip bubble fits a short label only, is clipped at the viewport edge when long — so the notice opens as a hover card rather than a tooltip: after a short dwell the pointer can move onto it, rest there and select its text, which a four-line notice has to allow, and Escape closes it, the side whose viewport fit can flip). The remaining-amount row (`API 剩余金额`) renders larger than the spend rows below it (今日 Token and 今日花费). Below today's bucket lines the panel ends with the **today session-spend ranking** (`今日会话花费`): conversations sorted by today's cost, highest first — one row per conversation, because the host has already merged each subagent session's spend into the row of the session that delegated it — each row a fixed right-aligned rank column, then the same middot separator the cost breakdown uses ("·" with the same size, tone, and spacing), then the session's durable title (renames sync automatically), then its amount — the title keeps its indented rank column; at most `SESSION_RANKING_LIMIT` (10) rows render, with a "…还有 N 个会话" hint for the rest. Refreshing keeps the last values visible rather than blanking them, and a refresh failure retains the last good value. A session or day without priced usage shows a word rather than a fabricated figure: "no usage recorded" when nothing was measured, and "recorded, but no rate matched" when usage was measured that no pricing row covers — the unpriced models are then listed by name, because a silent ¥0 is otherwise indistinguishable from an idle day. A failure — no API key configured, a rejected credential, a transport error — renders a muted "Balance unavailable" chip that OPENS the same panel the amount does: its first row is the short localized `notice.unavailable` (whose prefix is that same word) telling the reader to check the API key — the Remote's verbatim English message is not rendered, it stays on the chip's accessible name and in the host log — the headline reads `—` because the total is unknown, and the refresh action sits where it always does, so a rejected credential is actionable and retryable from one place. An API key the API answers for but reports without any spendable balance is the other empty: nothing failed, so the chip keeps the ordinary label with its `—` amount and the panel's first row is `notice.none` alone. Neither empty hides the day: the spend comes from the session logs, so the chip's second line and the panel's 今日 Token / 今日花费 rows stay visible and current.

The package also contributes the **turn-cost entry** (`billing-turn-cost`, order 20) to ui-chat's `conversation.chat.assistant-actions` list slot — the same strip `ui-message-feedback` uses, so entries coexist; the entry's own CSS `order: 1` sorts it after every order-0 sibling, so the amount lands at the **end** of the actions row (after the clock). The entry renders a plain static `¥X` (no icon, no label, no interaction) for each completed turn's closing assistant message, resolved from a shared per-session `messageId → cost` map (`billing/getSessionTurnSpends`, one fetch per session, coalesced across concurrently mounting rows; a message id the map does not know triggers exactly one refetch for a newly completed turn). Turns that priced to zero (no DeepSeek usage) and failed loads render nothing, so a Remote outage never clutters the row.

A third entry, the **composer spend pill** (`billing-spend`, order 20), rides ui-conversation's `conversation.composer.dock` list slot — the stat row under the input box that ui-chat's own time/token pills occupy. `b6726fe79d` turned that dock from a column stack into one centred flex row (`InputBar.module.css` `.dock`), so a dock entry is an inline flex item rather than a row of its own: ui-chat's stats register `order: 0`, this entry `order: 20`, and the composer renders ContextMeter after the slot — the row therefore reads `[time/tok] [¥ pill] [ContextMeter]`, the pill immediately right of the built-in tokens (ContextMeter hides itself while a turn runs, and the dock itself only renders on a resident composer with a session, so the hero page shows no pill at all). Its own metrics are copied from ui-chat's `StatsPills.module.css` — the built-in pills of that same row — so the two read as one family: the same 12px font formula (`calc(var(--dsh-content-font-size-secondary, 13px) - 1px)`), tabular figures, tertiary tone, 14px glyph, `padding: 1px 8px`, 24px radius, 6px gap, and the same hover fill; below 480px the amount folds away so the glyph alone carries the entry (as the sibling per-message usage pill does). The entry is one billing-mark pill (the package's own ring-and-sparkle mark, with the sparkle filled in for the 14px glyph tier) showing the conversation's billed spend, opening a cost card that reproduces ui-chat's token-usage dialog skin token for token (menu surface, 12px radius, elevation-prominent, 16px padding, heading row with its headline amount and a 0.5px rule, right-aligned tabular detail grid): the heading is `花费金额` / `Spend`, and its three rows are the spend's three billing buckets under the wording that token card uses — **未缓存输入 / 缓存读取 / 输出**. The amount is the CONVERSATION's, merged exactly as the host's own sums merge it — and the pill is the only surface that shows it, the badge's second line and its panel both reporting the day: this session's own spend from the pushed `billingTodaySpend` projection (no Remote call of its own; `spendBuckets.ts` sums the per-model rows and absorbs the four-decimal float residual into the largest bucket, so the three rows always add up to the total the heading shows) with `billing/getSessionSpend` as the projection-less fallback, **plus** the subagent subtotal from `billing/getDelegatedSpend` through `sumSpends` — so the pill and the badge can never disagree — and it renders at the badge's own precision (`formatSpendSignificant`). A session that priced nothing anywhere shows no entry; a session that priced nothing ITSELF but delegated a subagent that did still shows, because the hidden rule runs on the merged amount. DSH keeps its own equivalent dialog seat in a private client bundle, so dismissal and placement were rebuilt from the two public primitives (`useAnchoredPosition` plus `useDismissOnOutsidePointer`).

The badge is account-level even though the slot is session-scoped: the header utilities row is simply the one always-visible title-bar seat the shell offers, and the balance it shows does not vary by session — but the spend lines do, because they price the current session's own usage (the pushed projection, or `billing/getSessionSpend`) and every session's usage through `billing/getTodaySpend`. Copy goes through the package's own `billing` locale namespace; styling uses tokens only.

## Today's consumption from the balance series

The figure riding the `API 剩余金额` row is pure account arithmetic, not token pricing: the **first balance queried on the current local calendar day** minus the amount on screen, plus every top-up the series showed in between. A top-up is an observed INCREASE rounded **up to the next ¥10 step** (the provider only tops up in round tens, so a ¥9 rise after a ¥10 top-up and ¥1 of spend still reads as ¥10), which is what keeps a day that was topped up and then spent down from reporting a negative consumption. That is the caliber of the `balanceinfo` desktop program this mirrors (`utils/balance.ts` + `Dashboard.tsx` there), and it is deliberately a SEPARATE figure from the priced 今日花费: this one is the account's own arithmetic, so spend from another client — or from before this browser was open — shows up here and nowhere else. The two figures legitimately differ.

Every balance this half queries is folded into a day record (`balanceDay.ts`) that persists through `localStorage`, so the day's baseline survives a reload and a `dsh` restart; the record rolls over on the **local** calendar day (the browser's day, not the host's Beijing day key — only the browser knows which day the reader is in), and the figure restarts from the new day's first query. It renders only once today holds a sample for the amount's currency: nothing measured renders nothing rather than a `¥0` a reader would take for a measurement. `getCachedBalance` replays a value an earlier query already recorded and never samples, so a session switch cannot move the baseline.

Because the balance is sampled on mount, on the manual refresh, and — while the page is visible — every five minutes (the `balanceinfo` program's own cadence), a top-up and a spend-down landing inside one five-minute window are seen as one net move; the ¥10 step is what keeps that from reading as negative consumption. Switching sessions samples nothing: the balance does not vary by session, so a switch re-reads only this session's own spend. The figure therefore reflects this page's own samples rather than a minute-by-minute ledger, and a hidden page stops polling and refreshes once on return.

## Refresh mechanics

The spends follow the conversation and the balance is cached and polled:

- **Reads are split by what they depend on** — `billing/getSessionSpend` and `billing/getDelegatedSpend` vary by session and re-run on a switch; `billing/getBalance` and `billing/getTodaySpend` do not, so they keep their own cadence (mount, manual refresh, turn settle, and a panel open for the day row) and a switch never re-reads them. Re-reading them was what kept the header spinner turning — and the day's token figure lagging behind the balance — on every switch.
- **Session spend is pushed, not fetched** — the host folds each session's spend into the client-visible `billingTodaySpend` projection and pushes every change; the composer spend pill is the surface that consumes it, subscribing with the framework `useProjection` seat, so the conversation's own amount is live with zero Remote calls while the projection registry is composed. When the key is absent, the same amount falls back to `billing/getSessionSpend`. The badge still runs this session's read group (one cached host pass, shared with the pill's own), but nothing it renders reads the result any more: its second line reports today's spend, which is account-level and has no pushed source behind it.
- **Today's spend follows settled turns, debounced — and forces** — the component subscribes to the current session's running flag through the framework `useSession` seat. When a prompt turn settles (the flag flips back to idle) it recomputes today's spend (`billing/getTodaySpend(true)`; the 今日 Token figure on that same row is summed from the returned model rows in place, with no extra request); the recompute is debounced for two seconds, so a burst of turns (an agent continuing across turns) prices once instead of once per turn. The read **forces**, because the turn just changed the answer: a plain read is handed the value from before the turn with a refresh running behind it, which reports each turn's cost one turn late. The same settle forces this session's delegated subtotal (`billing/getDelegatedSpend(sessionId, true)`), which is what keeps the pill's amount a whole-conversation figure as subagents finish. The ranking (`billing/getTodaySessionsSpend`) is fetched only while the detail panel is open (and forced on refresh), so a badge that stays closed never pays for the all-session scan, and the ranking can be up to 60 seconds behind afterwards.
- **Opening the panel re-reads today's spend** — a switch re-reads only the session's own lines, so while the user browses conversations the day row holds whatever the last read returned; opening the panel is the moment the reader asks for it, and it re-reads `billing/getTodaySpend` beside the ranking. Both take the cached path (no `force`): the host serves what it holds, and past its window refreshes behind the answer.
- **Balance is TTL-cached and polled** — the account balance is fetched on mount and on the explicit refresh action. The host reuses one snapshot for up to 15 seconds (`force` on the manual refresh bypasses it) and aborts a request after 5 seconds; the browser keeps the last settled value so a session switch renders the amount immediately, without re-reading it (the balance does not vary by session). On top of that the badge polls every `BALANCE_POLL_MS` (5 minutes) while the page is **visible**, paused while the document is hidden and refreshed once when it returns: the balance-series consumption is measured from the first balance each local day queries, so the sampling cadence is that figure's resolution.
- **Refresh keeps the last values** — an in-flight refresh leaves the previous values on screen, and a failed refresh retains the last good value instead of blanking it. The refresh action calls `billing/getBalance(true)`, `billing/getTodaySpend(true)`, `billing/getDelegatedSpend(sessionId, true)`, and `billing/getTodaySessionsSpend(true)`, which bypass the host-side caches; the mount, the panel-open and the session-switch reads use the cached path, while the settled-turn recompute forces exactly as the refresh does. The spinner follows the group a change actually re-ran: a session switch covers this session's two reads only, a manual refresh covers every read.

## Plugin manager metadata

The plugin manager shows this package's row with a localized title and description plus an icon, all read from the package itself (the host evaluates no plugin code):

- `locale/en.json` and `locale/zh.json` — `{"meta": {"title": …, "description": …}}`, resolved against the active interface language with English as the fallback.
- `icon.svg` — a self-contained SVG (no external font or image references), declared as the package's top-level `icon` field.

Both are resolved through the package's `exports` map, so `./locale/*.json` must stay exported — dropping it makes the locale files resolve to `ERR_PACKAGE_PATH_NOT_EXPORTED`, which the host treats as "no metadata" and silently falls back to the bare package name. `locale/*.json` and `icon.svg` must also stay in `files`, or a packed tarball ships neither.

## Model Experience

None, as this package renders account-level provider facts for a human and touches no prompt, message, schema, stream, or tool result. The model's own view of provider quota lives with the `QUOTA` / `INVALID_CREDENTIAL` error codes surfaced by [`dsh-llm`](https://github.com/deepseek-ai/deepseek-harness/tree/main/packages/llm/llm) on failed requests.

#### KV Cache effect

None; the package never assembles or sends provider requests, and its one RPC is a credential-authenticated account read that is not cached in the provider KV store.

## Known Limitations and Deferred Work

- **First balance line only** — the balance reads the primary (`balance_infos[0]`) currency line; other currency lines are not shown.
- **Ranking capped at 10** — the panel shows at most `SESSION_RANKING_LIMIT` conversations, with a "…N more sessions" hint. The cap applies after the host's subagent roll-up, so one row is one conversation rather than one delegation.
- **The delegated subtotal moves with the turn, not per event** — the pill amount's own part is live (the pushed projection moves as the turn streams), while the subagent part comes from `billing/getDelegatedSpend` on mount, on a session switch, on manual refresh, and when a turn settles, served from the same 60-second host cache as today's spend. A subagent that burns money mid-turn therefore lands on the conversation's amount at the next read, not per event.
- **Turn cost needs a finalized closing message** — interrupted turns have no actions row, so no turn cost is shown for them.
- **Today's tokens count priced rows only** — the figure sums the three billing buckets of the model rows `billing/getTodaySpend` returns (models with a rate row), so a model without one contributes no tokens; cache writes ride the cache-miss bucket. The hit-rate figure riding that row takes the prompt side only — cache read over cache read plus uncached input — so output tokens never enter its denominator, exactly the split DSH's own `billedInputTokens` makes. The panel types in exactly **three levels**, defined once as custom properties on `.panel` in its stylesheet with every member referencing its own level's tokens: **level one** 11px/16px tertiary tabular-nums for the bucket detail lines (`未缓存输入 ¥X · 缓存读取 ¥Y · 输出 ¥Z`), a whole today session-spend ranking row (rank, middot, title, amount), the "…N more sessions" footer, and the two trailing figures (today's consumption from the balance series after the amount, and the day's cache-hit share); **level two** 12px/18px secondary for the 今日会话花费 title — the panel's only level-two member, and it carries no number, so the level keeps no number tone of its own (a future level-two amount would want one, text and numbers being allowed to differ in tone); **level three** 13px/18px primary tabular-nums for the 今日 Token and 今日花费 rows.
- **The composer spend pill reads the delegated subtotal on its own schedule** — it re-reads `billing/getDelegatedSpend` on mount, on a session switch, and (forced) on the turn-settled edge, with the same two-second debounce the badge uses, so the two surfaces issue one forced delegated read each per settle. That duplication is deliberate for now — the host's revision gate makes the second pass cheap — and a shared per-session store (the `turnCostStore` pattern) is deferred until the logs show it matters. The pill prices what the host's table prices (DeepSeek and MiMo) while the token row beside it counts every token, and cache writes ride its uncached-input row.
- **Balance is up to 15s stale between polls** — the host reuses one snapshot for 15 seconds and the browser keeps the last settled value, so spending from another client moves the shown value at the next poll (5 minutes while the page is visible, none while it is hidden), at a manual refresh, or at a browser reload.
- **The balance-series consumption is what THIS browser has seen** — it is bucketed by the browser's local calendar day and samples on mount, on the manual refresh, and on the 5-minute visible-page poll (a session switch samples nothing: the balance does not vary by session), so it reflects this page's own samples rather than a continuous ledger, and a top-up landing between two samples surfaces only in the net move the ¥10 step rounds up. The day record lives in this origin's `localStorage`, so another browser — or a cleared store — starts from its own first sample of the day.
